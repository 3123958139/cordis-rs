# 基于“核心下沉”架构的 dsh-rs 开发方案

> **版本**：v2.0（架构重构版）  
> **状态**：待评审  
> **核心思想**：Rust 写引擎（重计算/重I/O/重安全），TypeScript 写车身（重编排/重动态/重UI）


## 一、背景与设计哲学

### 1.1 为什么放弃“纯 Rust 复刻”路线

原计划试图用 Rust 在 `cordis-rs` 之上 100% faithful 复刻 deepseek-harness，包含 Web UI、插件 HMR、动态配置加载等全部功能。这一路线存在三个根本性矛盾：

1. **Rust 不适合做高频变动的上层逻辑**：Prompt 模板、工具注册、配置解析在 AI 应用开发中迭代极快，Rust 的编译型特性天然不适合这类“改一行等30秒编译”的场景。
2. **异步模型冲突难以调和**：`cordis-rs` 的事件系统是同步的，而 Agent 循环、LLM 流式、工具执行天然是异步的。强行在同步事件中桥接异步会导致复杂的死锁风险。
3. **插件 HMR 在 Rust 中代价过高**：动态库加载涉及 ABI 稳定性、unsafe 代码和资源泄漏风险，投入产出比极低。

### 1.2 “核心下沉”架构的设计原则

**Rust 层（引擎）** —— 做 TS 做不好或做不快的：
- 高并发 Agent 循环调度（Tokio 运行时）
- 工具执行的系统级沙箱（seccomp/Landlock）
- 会话日志的持久化与索引
- LLM 流式请求的强类型解析

**TypeScript 层（宿主）** —— 做 Rust 做起来很痛苦的事：
- Web UI 服务端与前端
- 配置解析与热更新（cordis.yml）
- 插件动态发现与 HMR
- Prompt 模板组装与工具 Schema 生成

**通信协议**：JSON-RPC 2.0 over Stdio（进程间通信，零网络开销，天然跨语言）。

### 3.3 Agent 循环核心实现

```rust
pub struct AgentLoop {
    llm: Arc<dyn LlmAdapter>,
    tools: Arc<ToolRegistry>,
    sessions: Arc<SessionStore>,
    max_iterations: usize,
}

impl AgentLoop {
    pub async fn run(
        &self,
        session_id: &str,
        prompt: &str,
        mut event_sink: impl EventSink,
    ) -> Result<AgentOutput> {
        // 1. 追加用户消息到会话
        self.sessions.append(session_id, SessionEvent::UserMessage {...}).await?;
        
        let mut messages = self.sessions.derive_messages(session_id);
        let mut iteration = 0;
        
        loop {
            if iteration >= self.max_iterations {
                break;
            }
            iteration += 1;
            
            // 2. 调用 LLM
            let stream = self.llm.complete(LlmRequest {
                messages: messages.clone(),
                tools: self.tools.list_schemas(),
            }).await?;
            
            // 3. 处理流式响应
            let mut assistant_content = String::new();
            let mut tool_calls = Vec::new();
            
            while let Some(event) = stream.next().await {
                match event {
                    LlmStreamEvent::Chunk(delta) => {
                        assistant_content.push_str(&delta);
                        event_sink.emit(StreamEvent::Chunk(delta)).await?;
                    }
                    LlmStreamEvent::ToolCall(tc) => {
                        tool_calls.push(tc);
                    }
                    LlmStreamEvent::Done => break,
                    LlmStreamEvent::Error(e) => return Err(e.into()),
                }
            }
            
            // 4. 追加助手消息
            self.sessions.append(session_id, SessionEvent::AssistantMessage {...}).await?;
            
            // 5. 如果没有工具调用，结束循环
            if tool_calls.is_empty() {
                break;
            }
            
            // 6. 执行工具调用
            for tc in tool_calls {
                let tool = self.tools.get(&tc.name)?;
                let result = tool.execute(tc.args).await?;
                self.sessions.append(session_id, SessionEvent::ToolResult {...}).await?;
                // 将工具结果加入消息历史
                messages.push(ChatMessage::tool_result(tc.id, result.content));
            }
        }
        
        Ok(AgentOutput::new(session_id, messages))
    }
}
```

### 3.4 沙箱设计（Linux 实现）

使用 Landlock + seccomp 构建多层防护：

```rust
pub struct LinuxSandbox {
    allowed_paths: Vec<PathBuf>,
    allowed_commands: Vec<String>,
    memory_limit: Option<u64>,
    cpu_limit: Option<u64>,
    network: NetworkMode,
}

impl Sandbox for LinuxSandbox {
    async fn execute(&self, cmd: &str, args: &[String]) -> Result<SandboxOutput> {
        // 1. fork 子进程
        // 2. 在子进程中按顺序应用隔离：
        //    a. 创建 user/mount/network namespaces
        //    b. 丢弃 capabilities，设置 no_new_privs
        //    c. 应用 Landlock 文件系统规则（白名单路径）
        //    d. 安装 seccomp-BPF 过滤器（默认拒绝）
        // 3. exec 目标命令
        // 4. 通过 cgroups v2 限制资源
        Ok(SandboxOutput { stdout, stderr, exit_code })
    }
}
```

**网络策略**：
- `none`：完全无网络
- `loopback`：仅本地回环
- `full`：完整网络（需额外审批）

> **注**：macOS 使用 `sandbox` 和 `Seatbelt` 实现类似隔离。

```rust
use tokio_jrpc::{App, Error};
use serde::{Deserialize, Serialize};

#[derive(Debug, Deserialize)]
pub struct RunRequest {
    pub session_id: String,
    pub prompt: String,
    pub model: Option<String>,
    pub max_iterations: Option<usize>,
}

#[derive(Debug, Serialize)]
pub struct RunResponse {
    pub session_id: String,
    pub messages: Vec<ChatMessage>,
    pub turn_count: usize,
}

pub struct RpcHandlers {
    state: Arc<EngineState>,
}

impl RpcHandlers {
    pub async fn run(&self, params: RunRequest) -> Result<RunResponse, Error> {
        let output = self.state.agent_loop.run(
            &params.session_id,
            &params.prompt,
            self.state.event_sink.clone(),
        ).await?;
        Ok(RunResponse { ... })
    }
    
    pub async fn session_events(&self, session_id: String) -> Result<Vec<SessionEvent>, Error> {
        Ok(self.state.session_store.load_events(&session_id).await?)
    }
    
    pub async fn fork_session(&self, source: String, boundary: u64, child: String) -> Result<(), Error> {
        self.state.session_store.fork(&source, boundary, &child).await?;
        Ok(())
    }
}
```

### 4.2 Rust 引擎进程管理

```typescript
// packages/dsh-host/src/engine.ts
import { spawn, ChildProcess } from 'child_process';
import { EventEmitter } from 'events';

export class EngineProcess extends EventEmitter {
  private proc: ChildProcess | null = null;
  private rpcClient: RpcClient;
  
  async start(enginePath: string, config: EngineConfig) {
    this.proc = spawn(enginePath, ['--stdio'], {
      stdio: ['pipe', 'pipe', 'pipe'],
    });
    
    // 初始化 JSON-RPC 客户端（使用 newline-delimited JSON）
    this.rpcClient = new RpcClient(this.proc.stdout!, this.proc.stdin!);
    
    // 监听进程退出
    this.proc.on('exit', (code) => {
      this.emit('exit', code);
    });
    
    // 发送初始化配置
    await this.rpcClient.request('initialize', config);
  }
  
  async runAgent(sessionId: string, prompt: string): Promise<RunResponse> {
    return this.rpcClient.request('run', { session_id: sessionId, prompt });
  }
  
  async getSessionEvents(sessionId: string): Promise<SessionEvent[]> {
    return this.rpcClient.request('session_events', { session_id: sessionId });
  }
  
  async forkSession(source: string, boundary: number, child: string): Promise<void> {
    await this.rpcClient.request('fork_session', { source, boundary, child });
  }
  
  async stop() {
    this.proc?.kill();
  }
}
```

## 五、通信协议规范（JSON-RPC 2.0）

### 5.1 协议基础

- **传输**：Stdio（stdin/stdout），newline-delimited JSON
- **格式**：JSON-RPC 2.0
- **方向**：TS → Rust（请求），Rust → TS（响应 + 流式事件）

### 5.2 请求方法

| 方法 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `initialize` | `{ model, apiKey?, baseUrl?, maxIterations?, sandbox? }` | `{ version, status }` | 初始化引擎 |
| `run` | `{ session_id, prompt }` | `{ session_id, messages, turn_count }` | 运行 Agent |
| `session_events` | `{ session_id }` | `SessionEvent[]` | 获取会话事件 |
| `fork_session` | `{ source, boundary, child }` | `{}` | 分叉会话 |
| `list_sessions` | `{}` | `{ sessions: string[] }` | 列出所有会话 |
| `delete_session` | `{ session_id }` | `{}` | 删除会话 |

### 5.3 流式事件（Rust → TS 推送）

Rust 引擎在执行 `run` 过程中，通过 JSON-RPC 通知（Notification）向 TS 推送事件：

```json
{"jsonrpc":"2.0","method":"event","params":{"type":"assistant/chunk","delta":"Hello"}}
{"jsonrpc":"2.0","method":"event","params":{"type":"tool/call","tool":"bash","args":"ls -la"}}
```

## 八、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| Stdio 通信成为性能瓶颈 | 高并发时消息序列化开销 | 中 | 预留 Unix Socket 作为备选传输 |
| Landlock 在旧内核不可用 | Linux < 5.13 无法使用 | 低 | 降级到 seccomp-only 模式 |
| 沙箱实现跨平台困难 | macOS/Windows 支持不足 | 中 | 优先 Linux，macOS 次之，Windows 做基础支持 |
| TS 与 Rust 类型不一致 | 运行时类型错误 | 中 | 使用 `ts-rs` 或 `qubit` 自动生成 TS 类型 |
| 引擎进程崩溃 | 服务中断 | 低 | TS 层实现进程健康检查和自动重启 |


## 九、总结

本方案的核心思想是 **“各取所长”** ：

- **Rust 层**：提供高性能、高安全的 Agent 引擎，编译为单一静态二进制，通过 JSON-RPC 2.0 over Stdio 对外服务。
- **TypeScript 层**：提供灵活的配置系统、插件热更新、Web UI 和 CLI 体验，复用 deepseek-harness 的上层设计。

两条技术栈通过 **明确定义的 RPC 协议** 解耦，各自独立演进。Rust 引擎可以替换实现而不影响 TS 上层，TS 上层可以快速迭代 UI 和配置而不触及核心逻辑。

**最终交付物**：
1. `dsh-engine`：Rust 二进制（Linux/macOS/Windows）
2. `dsh-host`：npm 包（含 CLI 和 Web UI）
3. 完整的 `cordis.yml` 配置文档和示例
